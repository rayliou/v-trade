# 实施与产品化：用有限研究投入购买一个继续或停止的答案

日期：2026-09-13；状态：建设建议。用户已确认本金 20万–40万美元、目标超过 QQQ、回撤合理、可能使用 LEAPS、数据费用每年≤1,000美元。本轮只完成文档审查和情景计算，没有进行采购、策略开发或实盘交易。

## 1. 建议的第一轮投入上限

首轮以 **100–160 小时**工程与研究投入为规划范围；每周约 20 小时约需 5–8 周。时间是估计，不是交付承诺。供应商数据需要大量修复、账户迟迟不可用、统计证据不足时，调整范围或结论，不能自动延长成完整平台。

数据全年≤1,000美元为用户约束，基础首选见 [05](05-data-and-engineering.md)。计算、存储和个人时间另行核算，不能用数据低价掩盖工程成本。第一阶段无需付费 LLM、云仓库或专门 GPU。

| 阶段 | 工时估计 | 产出与退出条件 |
|---|---:|---|
| P0：冻结研究条件 | 8–12 | 本金口径、QQQ 主基准、风险阈值提案、费用口径、实验表；若偏好未确定先保留多个风险情景 |
| P1：历史数据与会计 | 28–44 | 可复现下载/导入、证券时点与公司行动验收、简单基准账本；错误未清则不进入策略胜负判断 |
| P2：固定候选实验 | 32–52 | 03 的动量、质量和 10/20 只对照，成本与封存协议；输出包括失败版本 |
| P3：复核与小型输出 | 20–32 | 置信区间、稳健性、QQQ 对照、ROI、周度摘要与风险日志；给继续/证据不足/停止结论 |
| 缓冲 | 12–20 | 数据或实现问题定位；实际用完须说明原因，不默默扩大范围 |

区间相加为 100–160 小时，与 ROI 的 160 小时上侧情景一致。先完成研究闭环，之后才为真实高频使用需求添加界面。

## 2. 调整原来的开发顺序

PIT 股票池和基本面从原 Phase 2 前移到第一个质量回测之前；账户目标、现金与风险限制从 Phase 7 前移。复杂的 options、regime、graph 和 event 层没有天然顺序，后续依据实际剩余问题和增量价值安排。

保留基本原始数据适配接口即可，不提前同时维护多供应商全套实现。小表和周报应先回答“本周为什么变、是否达到规则、有什么数据问题”，不先做几十列实时仪表盘。

### 股票模型通过后的候选队列

1. 若回撤是主要不足，先比较简单仓位控制或核心+卫星配置，与 QQQ+现金对照。核心+卫星可能降低偏离痛苦，但也稀释超额收益；不能仅因更平稳就宣称超过 QQQ。
2. 若基本面反应迟缓，先调查真正的 PIT 预测修正样本及报价；仍在 1,000 美元数据总预算内才可试。
3. 若人工研究主要耗在关系查证，用少量有来源标签管理当前组合；只有维护成本和错误率改善被观察到才扩展为图。
4. 若确有期权风控/LEAPS需求，比较有限历史试验与前向记录的成本，单独验证成交和工具风险。
5. 若需要事件抽取，先从 SEC 公告开始，准备人工标注小样本，统计字段正确率、来源可定位率、漏报与虚报；抽取准确并不自动证明有投资收益。

每项升级都需要明确“没有它的冻结版本”和“加上它的版本”之间差别。解释性功能可以按时间节省和风险覆盖评价，不强制虚构 alpha，但也要有成本边界。

## 3. 影子运行与人工复核

历史结果合格后先做 3–6 个月不下单的影子记录：每日自动运行/故障状态、每周候选与变化原因、每月规则组合与假定成交。用户有实际账户时，可将只读持仓另账比较。

拟议操作质量要求：交易决策相关缺失全部解释；所有候选和复核行为可追溯；月度组合生成可重放；每周维护目标≤30分钟，持续记录是否实现。30分钟是使用目标，首年20小时维护是 ROI 假设，两者并不保证自动一致，按真实年累计改算。

人工否决与接受写入时间和理由：系统是否忽略了已知事实？用户是否因为短期价格波动偏离计划？规则组合、人工组合和成交组合分别留存，否则无法判断是模型失效还是执行差异。

小额实盘是后续投资决定，不在这份文档审查中默认执行。模型经历一个上涨季度并不证明能跨周期持有，也不足以据此启用杠杆。

## 4. 哪些结果说明值得继续

- 对 QQQ 的扣成本优势满足 02 的经济门槛，并且回撤、Ulcer 与水下时间可接受；优势在成本压力和合理参数变化下仍存在。
- 运行可靠、解释有数据依据、用户确实更容易执行规则；没有被高频警报诱导过度换仓。
- 实际数据和运行费用、工时符合预算，复杂功能增加后仍有净价值。

若结果不超过 QQQ，本次收益目标即未达成。若只体现体验和研究效率价值，可将项目收缩成已有投资组合的风险观察器与研究日志；须明确它与“跑赢 QQQ 的策略”是不同交付。

如果结果区间跨越零、近期样本很短，不应马上继续堆特征。冻结模型与真正前向记录比继续挑参数更有信息价值。

## 5. 产品化应拆成不同经营问题

| 形态 | 需要证明的价值 | 新增依赖 |
|---|---|---|
| 个人研究工具 | 帮助本人形成有证据的决策、控制风险和时间 | 个人数据授权、单用户运行稳定性 |
| 对外研究/排名产品 | 外部用户愿意为解释、工作流或数据整合付费 | 商业数据及衍生输出权利、用户隔离、支付与支持、真实需求验证 |
| 个性化建议/自动执行 | 投资适配与可靠执行 | 具体地区业务资格评估、券商权限、订单/资金保护、审计与故障恢复 |

个人策略有效不等于产品有市场；产品有人付费也不等于策略有 alpha。对外产品的单位经济应另建：

```text
月贡献利润 = 付费用户数 * (月价格 - 每用户变动成本)
             - 商业数据固定费 - 支持及基础设施固定费
```

当前没有访谈、付费意愿、客户留存或商用数据报价，不能计算有意义的商业 ROI。优先验证个人用途；在长期可用性和需求证据出现后，再决定是否为产品化投入。个人版的数据价格不能作为商用产品的成本预算。[Sharadar 许可范围](https://sharadar.com/terms)。
